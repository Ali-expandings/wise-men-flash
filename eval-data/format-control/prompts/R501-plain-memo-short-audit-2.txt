[S32] Load-test the heavy queries before each table goes live.

[S35] - If you profile your actual heaviest queries at real data volume (watch for skewed tenants with much larger row counts) and find a regression that indexing/partitioning genuinely can't fix, I'd scope RLS to the higher-risk tables only rather than blanket-applying it, and treat the rest as a longer-term project.

[S39] - If you're heading toward a compliance review (SOC 2, enterprise security questionnaires), that pushes further toward RLS, not away — "is tenant isolation enforced at the database layer or only in application code" is a standard question, and app-only isolation is a known red flag in vendor reviews.
